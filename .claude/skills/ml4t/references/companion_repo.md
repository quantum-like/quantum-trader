# Companion repository map

> `github.com/stefan-jansen/machine-learning-for-trading` (3rd ed. on the default branch; `git checkout second-edition` for the old code). It is "a teaching and demonstration repository", explicitly "not a research platform and not a production trading system": 27 chapter directories of Jupytext notebooks plus nine case studies carried Ch6 -> Ch20 through one shared pipeline and a content-addressed experiment registry. Use it to (1) open the notebook that demonstrates a method, (2) reuse `utils/` and `case_studies/utils/` as patterns (fold preparation, registry identity, backtest runner, coverage gates), (3) reproduce the book's numbers from released artifacts without retraining, (4) run reduced experiments in an isolated workspace. Do not use it as a strategy library or a live system. Everything below came from READMEs, docstrings and source digests; "(inference)" marks claims not verified in source. Paths and the few line references refer to the 2026-10-02 snapshot.

- Platform rule: Linux -> Docker or uv; Apple Silicon -> uv; Intel Mac -> Docker only (no PyTorch x86_64 wheel); Windows -> WSL2 only (native Python unsupported). Disk ~16 GB local (11 env + 4 data + 0.9 git).
- Support levels (`docs/what-this-is.md`): (1) reproduce directly, (2) modify with config edits, (3) full retrain / GPU / AlgoSeek, (4) not promised: profitable strategies, live deployment, support.
- Working-directory contract: loaders resolve `data/` relative to cwd unless `ML4T_DATA_PATH` is absolute; `uv run` does not read `.env`, so export it. `No module named 'utils'` means you ran from a subdirectory.
- Notebook parameters: every notebook has a `# %% tags=["parameters"]` cell with production defaults (`MAX_SYMBOLS = 0` = all, `N_EPOCHS`, `START_DATE`, `MAX_TRAIN_ROWS`, `MAX_FOLDS`, `CV_FOLDS`, `BATCH_SIZE`, `LOOKBACK`, `TOP_K`, `TOP_N_PREDICTIONS`, `FORCE_REBACKTEST`, `SPLIT`); one code path, no `if TEST:` branches.

`ModelingDataset` fields: `dataset` (Polars), `feature_names`, `panel_feature_names`, `label_col`, `date_col` (`timestamp` else `date`), `entity_cols` (sorted by cardinality desc; `[0]` is the primary entity, constant columns dropped), `splits`, `label_buffer`, `task_type`, `class_values`, `temporal_by_fold` (LazyFrame; read via `fold_temporal_frame`, never index directly), `temporal_keys`, `feature_dtype`, `eval_label_col`, lazy `input_lineage` (`schema_version 1`, `fingerprint`). Joins: features LEFT JOIN temporal (`unique(keep="last")`) then INNER JOIN labels; preprocessing per fold = `SimpleImputer(median) + StandardScaler` fit on `X_train` only; residual NaN/inf -> 0; `train_sample_frac` subsamples train only with `default_rng(RANDOM_SEED + fold_id)`.

Guardrails to carry into your own code:
- Supply the label buffer at call time (`generate_cv_splits(label_buffer="21D")`); `load_modeling_dataset` raises when no buffer is declared. With a calendar and `buffer_unit="sessions"`, `"21D"` means 21 trading sessions; `pd.Timedelta("21 days")` is ~15 sessions and under-buffers by ~6.
- Generate fold geometry from the unreduced label timeline before any `max_symbols` filter (reducing `cme_futures` to 5 products shifted every fold boundary 2 sessions earlier).
- Folds are oldest-first with `fold == position` since ml4t-diagnostic 0.1.4 (`_assert_chronological`); read boundaries, not list positions (`splits[:2]` flipped meaning at 0.1.4, #1076; `splits[0]["train_start"]` once discarded 3 years on `etfs`).
- `_purge_holdout_touching_validation` drops validation rows whose label outcome reaches the holdout; a fold left empty raises.
- Temporal (model-based) features must cover >= 95% of dates per window; warm-up gap excused only in train windows and only up to 10% (measured 4.8% and 6.1% on `crypto_perps_funding` 90-bar z-scores; a stale artifact shows ~50%).
- Score classification against the continuous return via `labels.classification_eval_label` (`Spearman(score, binary)` collapses to `2*(AUC-0.5)`).
- IC is NaN, not 0, when undefined (< 10 entities or all ties; #493). `conformal_quantile` uses rank `ceil((n+1)*coverage)` and returns `inf` when rank > n (n=5 cannot certify 90%).
- `verify_input_digests=True` after regenerations: the registry stores feature-set names only, so a model on corrected features and one on the leaky version otherwise share a `training_hash`.
- Predictions cache (`predictions_cache.py`): the spec dict is the cache key, so a hyperparameter left out of the spec silently reuses stale predictions; `notebook_cache_signature` folds the notebook's own source digest into the key.
- Column projection (`load_modeling_dataset(columns=)`): unknown names raise; join keys, date, entities, label and `fold` are always kept; `panel_feature_names` records the unprojected list that lineage hashes; a feature name present in both financial and model-based artifacts raises under projection (`us_equities_panel` reads 7 of 74 columns at 0.47 GB instead of 17.6 GiB).
- `PYTHONHASHSEED` set inside a kernel affects only subprocesses; launch the kernel with it set.

Identity scheme (`case_studies/utils/registry/specs.py`): `HASH_LENGTH=12` hex of SHA-256 over `canonical_json`; `IDENTITY_VERSION=3`, `LEGACY_IDENTITY_VERSION=2`, `SUPPORTED_IDENTITY_VERSIONS={2,3}`; `DEFAULT_SEED=42`; required spec fields `family, label, seed`; `preset_path` stripped before hashing. Chain: `training_hash = f(projected computation)` -> `prediction_hash = f(training_hash, checkpoint_value, split, checkpoint_kind, identity_version)` -> `backtest_hash = f(prediction_hash, hashable strategy_spec, identity_version)` -> population/cohort digest. Hashed inputs: label name + file digest; feature digests + exact column list; task type (+ class values); every fold's four boundaries; estimator class + per-fold effective params; imputer/scaler ids; checkpoint schedule; eligibility-manifest digest with row/fold counts; seed; runner identity: declared versions for linear/GBM (`LINEAR_RUNNER_VERSION`, `GBM_RUNNER_VERSION`, `FOLD_PREPARATION_VERSION=1`, `PREPROCESSING_ID="median-imputer-standard-scaler/v1"`, `GBM_PREPROCESSING_ID="lightgbm-native-float32/v1"`) and `LATENT_MODEL_VERSIONS={cae:1, ipca:1, pca:1, sae:2, sdf:1}` (`sae` is at 2 because `run_sae_fold_with_library` once omitted `batch_size`, the library read one full-panel batch, and those fits must not be reused), while tabular DL, sequence, latent-factor and causal identities carry a source-content digest plus version pins such as `SEQUENCE_RUNNER_VERSION=1`, `SEQUENCE_PREPARATION_VERSION=3` and `CAUSAL_RUNNER_VERSION=2` (the notes describe both mechanisms; the exact composition per family is inference); canonical-vs-preview flag + every reduction. Not hashed: notebook, git commit, write time, elapsed, device, threads (`runtime.py` is "explicitly outside every family's source identity"). Spec validation and portability: `_validate_spec` injects `seed=42` with a logged warning when missing and raises `ValueError` for any other missing required field; `canonical_value` refuses non-finite values and anything that fails a JSON round-trip; `_is_engine_default` does no cross-type coercion, so `1`, `1.0` and `True` never collapse into one hash.

Registry discipline (each enforced in code):
1. Populations are immutable and declared before execution; a half-finished sweep cannot pose as complete (`require_complete`, `partial_members`, `require_declared_menu_coverage`). If any config raises, nothing is published under the name; finished configs stay registered; re-run fits only what is missing.
2. Preview can never masquerade as canonical: writes under `<workspace>/.preview/<cs>`, must declare `preview_reductions`, reductions hashed into identity, barred from populations; relative preview workspaces resolve under `ML4T_PREVIEW_ROOT` (default `~/ml4t/artifacts/preview`) because on 2026-09-06 a 268K registry landed in the repo root. Preview keys per family: DML `{max_samples, max_symbols, n_folds, n_placebo}`; GBM `{checkpoint_interval, folds, max_iterations, max_symbols, train_sample_frac}`; LATENT `{folds, max_iter, max_symbols, n_epochs, n_epochs_cond, n_epochs_moment, n_epochs_unc, n_factors}`; LINEAR `{folds, max_symbols, train_sample_frac}`; SEQUENCE `{folds, max_symbols, max_train_sequences, max_predict_sequences}`; TABM `{checkpoint_interval, folds, max_symbols, n_epochs}`.
3. Released baseline is read-only (`PermissionError("released baseline is read-only; open a workspace to write")`); under `PYTEST_CURRENT_TEST` regeneration of the default release root is refused (a test once wrote 269 `backtest_runs` into the published registry).
4. Reporting notebooks call `read_only_study`, never `open_study` (`activate()` rewrites process-global `ML4T_OUTPUT_DIR`; a smoke workspace once showed 126 scored prediction sets vs the canonical zero). Entry point comes from `ML4T_ENTRY_POINT` or an explicit arg, never inferred.
5. Holdout geometry (`research/holdout.py`, `cv_window.canonical_window`): `evaluation.holdout_start/holdout_end` must both be declared in `setup.yaml`; `train_start = earliest_train_start(folds)`, `train_end = pre_holdout[-(buffer_steps + 1)]` counted in observations along the panel's own dates; buffer = widest over `labels.primary + variants` (a 1-day buffer handed to a 21-day model leaks via features; mixed units refused; no declared buffer refused); `buffer_steps >= horizon_steps`; intraday `holdout_end` widened to the last observation of that date; holdout fold id = max validation fold + 1. Cadence is measured, not assumed: `observation_step(...)` from the timeline, with `periods_per_year = max(1, round(n_obs / span_years))` as the fallback for month-denominated buffers (otherwise "1M" reads as 21 observations on a monthly panel where a month is one). `train_start_floor`: the family hook `holdout_training_floor` clamps `train_start` to where fold-scoped features exist (`sp500_equity_option_analytics` covered 495 of 977 training dates without it); the clamp is recorded in `request.train_start_floor` only when applied, so unaffected identities do not move. `refuse_a_second_look` -> `HoldoutWindowSpent` unless earlier generations are named in `retiring=` (`strategy_analysis.py`).
6. Holdout spec re-keyed to one fold (`research/holdout.py`, `research/models.py`): `_rekey_holdout_spec` dispatches `rekey_holdout_spec` per family (`NotImplementedError` naming the family otherwise); `_require_holdout_keyed_fields` checks exactly one fold, `expected_prediction_keys.n_folds == 1`, and `effective_params_by_fold` / `effective_class_weights_by_fold` keyed to the holdout fold id; `validate_locked_expected_keys` raises "no eligibility manifest" / "eligibility mismatch" at execution. `FOLD_DERIVED_FIELDS` (`computation.expected_prediction_keys`, `model.effective_params_by_fold`, `macro_context.resolved_fold_digest`) are the only fields `strategy_analysis._refit_comparable` ignores when deciding that a holdout run is a refit of the validation run.
7. Selection (`research/comparison.py`, `selection_field.py`, `strategy_analysis.py`): `best_validation_sharpe` orders by validation Sharpe with identity tie-break (`rank_one` -> lowest hash); label read off the winner via `label_of`; only complete members rank (`Result.complete` requires registry rows, spec and artifacts to agree via `_verified_digest`; `_complete_only` refuses to rank around incomplete backtests); retired generations excluded (`supersedes` lineage, never overwrite).
8. Sweep plans (`research/selection_field.py`) publish three populations (plan before execution, attempt at start, attestation only after a failure-free run); `_plan_in_force` requires complete + attested + covering the pool.
9. Prediction dispersion guard (`registry/registration.py`, `_validate_prediction_dispersion`) runs on every `register_prediction_set`: a per-fold score-scale/label-scale ratio above a bound set between 72.72 (healthy max over 8,090 folds) and 187.41 (divergent min, up to 9.22e39) is refused, except that the ratio is only logged (`refuse=False`) when the parent run declared a sampling reduction (`_sampling_reduced`) or a preview tier; non-finite scores are refused unconditionally.
10. Input artifact vintage (`registry/registration.py`): a run fitted on a different whole-file sha256 of a label/feature artifact cannot join the label's population unless `declare_artifact_supersession(cs, name, sha256=new, supersedes_sha256=old)` retires the old one; `scripts/check_input_artifact_vintage.py` previews.
11. Causal supersession (`registry/registration.py`, `registry/store.py`): a second canonical causal identity for a label must name the one it retires (`supersedes_hash`); `check_causal_supersedes` raises before the fit what `register_causal_run` would raise after; `declare_causal_supersedes` records retirement without refitting; readers resolve exactly one canonical identity per label (`current_causal_identities`), and `research/causal.causal_supersedes` offers a declared predecessor only when this registry actually holds it.
12. Hash is a cache key, not a training record: unchanged config reuses the stored result; "a new hash appeared" does not prove an override reached the model.

Guardrails that generalize beyond the repo:
- Coverage is checked absolutely against the declaration (folds present = folds declared; every declared session has >= 1 prediction), because relative checks "cannot see a failure that moves every peer the same way". A check that cannot run raises instead of returning an empty report (a `[]` once hid "wrote nothing" for a day). `_sealed` drops the end-of-validation sessions whose label outcome reaches past the boundary, so declared sessions exclude them (outcome-horizon seal); `_reject_label_mismatch` refuses to check a frame against a label it was not produced under; `assert_sessions_complete(known_absent=...)` refuses a session index missing an exchange session nobody declared absent.
- Conformal sizing lag: widths at `t` use residuals at or before `t - max(1, horizon_steps)`; entities with < 30 residuals get a pooled width (`pooled_prior_oos`); no coverage guarantee is claimed, widths are a volatility stand-in.
- Rank candidates on common support only (conformal/abstaining strategies trade fewer days); solvency required (`ruin` path unrankable); ties broken by lowest hash.
- Kill gates: gate 1 fails when validation Sharpe CI lower bound < 0; gate 2 fails only when the holdout-vs-EW Sharpe diff CI `excludes_zero_strong` AND point estimate < 0; `no_data` is reserved for missing bounds. Degradation classes (`classify_holdout_degradation`): `hold < -0.1` sign_flip; `|hold| < 0.05` signal_lost; both > 0 and `hold/val > 0.5` proportional, else signal_lost; None evidence_gap; otherwise degenerate.
- Block bootstrap length = `labels.rebalance_step` -> `_optimal_block_size` -> floored at the label horizon (`ret_5d` -> >= 5); `_distinct_trials` collapses identical return columns before DSR so duplicates do not inflate K; paired-bootstrap minimum n: 6 (ppy <= 12), 12 (<= 52), else 21.
- Vectorized runs thin predictions to non-overlapping rebalance dates (`labels.rebalance_step`, required per label, never inferred); prices load `warmup_periods` before the window so rolling allocators have history without reading past the end; missing vol at a decision time is filled from that date's cross-section only.
- Backtest runner refusals (`backtest_runner.py`): `_refuse_an_allocation_that_produced_no_target` refuses to register a run with no target weight at any rebalance; `_align_symbol_dtype` fails loudly on a dtype mismatch between predictions and prices; `substitute_continuous_return_for_classification(max_null_rate=_MAX_NULL_RATE)` swaps binary `y_true` for the continuous return; `warn_if_the_panel_does_not_bound_the_universe` warns when a price panel is not the universe a vectorized run trades.
- Causal placebo guards (`causal.py`): `_walk_forward_indices` builds expanding windows in rows or whole decision-time groups; `block_permute` keeps blocks inside contiguous runs split at gaps > `GAP_TOLERANCE_CADENCES=4` cadences; `_assert_placebo_permutation_possible` fails a refutation whose placebos equal the observed treatment; `PLACEBO_REQUEST_MARGIN=5` (`placebo_request_is_on_the_boundary`); `_frozen_fraction` reports the rows permutation could not move.
- Rank-1 selection requires full fold coverage and equal day counts (`IncomparableFoldGeometryError` otherwise); select once (`collect_rank1_per_cs`) then derive; pool IC over decision dates, not fold means.
- Fold seed coupling (`seed + fold_id`) makes renumbering folds a refit for tabular_dl/latent/sequence/reduced runs; never refit to recover a relabel (rule attributed to `AGENTS.md` rule 6 in docstrings; the file is not in the snapshot).
- Migrations reproduce before rewriting (`fold_renumbering`, `backtest_rekey`); a 2026-09-14 re-key once committed 37,484 broken references because `PRAGMA foreign_key_check` cannot see JSON-embedded hashes.

Per-fold effective params: linear `resolve_linear_params(cfg, X_train, y_train)` then `_quantize_derived`, recorded as `get_params(deep=True)` keyed by `str(fold)`; GBM `_GBM_REQUEST_FIELDS={checkpoint_interval, device, huber_alpha_scale, max_bin, max_iterations, num_threads}` stay top-level, every other override goes to `params`, each fold through `_validate_lightgbm_params`.

Configuration guardrails:
1. Prefer data-driven penalties: `alpha = alpha_frac * alpha_max` per fold (`alpha_max = max|X^T(y - ybar)| / n` on the standardized fold, divided by `l1_ratio` for ElasticNet) so "the family is never silently all-degenerate"; absolute `lasso_a*` grids can zero every fold on one panel and under-penalize another. Effective alphas are recomputed, never copied from a previous run. Detect: 100% zero coefficients on every fold.
2. Huber requires `huber_alpha_scale`: `delta = max(scale * nanstd(train_labels), float32 eps)`, quantized; `ValueError("Huber GBM configs must declare huber_alpha_scale or alpha")`; the scale is persisted so holdout can re-derive it.
3. Never hand-apply `dml.max_samples`: `resolve_causal_request` (`causal.py:1313-1318`) ignores it; `sp500_equity_option_analytics` once fit 37,240 of 376,871 rows and removing the cap flipped the sign of the estimate. A row cap enters only as a declared preview reduction.
4. L1 logistic uses `saga`, not `liblinear`: 3-class labels make multiclass liblinear a hard error in scikit-learn 1.8 (#740), and liblinear scales ~N^1.4 single-threaded (400k rows: 144.4 s vs 11.0 s; 1.2 M: 716.9 s vs 44.8 s; `06_linear` on `nasdaq100_microstructure` ran 7 h 23 m and was killed). Saga is also better OOS (log loss 1.0273-1.0276 vs 1.0293-1.0294). Use `tol=1e-3` when the penalty binds (C <= 0.1) because at 1e-2 coefficients strand near zero (24 vs 52 "non-zero" at C=0.01); use `tol=1e-2` for C >= 1 or saga hits the iteration cap. Detect: compare `(coef_ == 0).sum()` with `(abs(coef_) < 1e-8).sum()`.
5. `resolve_checkpoint_epochs` raises on out-of-range `checkpoint_epochs` instead of filtering (silent filtering hid the SDF global-vs-conditional epoch bug); `checkpoint_interval <= 0` means final only.
6. Stage constants override presets (documented wart): `09_dl_lstm`/`10_dl_tsmixer` ignore `n_epochs, batch_size, params.lookback` for `N_EPOCHS, BATCH_SIZE, LOOKBACK`; `08_tabular_dl` ignores `n_epochs, batch_size`; `11c`/`11e` fix `N_EPOCHS = 50`; `12_causal_dml` ignores `n_folds, n_placebo, max_samples, seed`; `07_gbm` on CPU substitutes the runtime seed. If an edit does nothing, look for a reassignment after `load_configs`.
7. Preset dispatch is not uniform: linear/gbm/tabular_dl run every listed preset; deep_learning runs only presets whose `params.architecture` matches the stage; latent_factors one fixed model per `11a-11e`; causal_dml only the first listed. An undispatched preset produces no hash.
8. Four repository-pinned declarations are read from the repo even under `ML4T_OUTPUT_DIR`: `labels.rebalance_step`, `labels.classification_eval_label`, `universe.cost_feasible`, `backtest.sweep.htm_cost_cascade.liquid_quantile` (fixed 0.20; `sp500_options` `12_backtest`/`13_portfolio_management` hardcode `LIQUID_QUANTILE = 0.20`). None reaches `backtest_hash`, so changing one requires starting from an empty `run_log/` or two methodologies mix in one registry. Changing `decision.cadence` requires a compatible `rebalance_step`. The readers that always consult the committed `CASE_STUDIES_DIR/<cs>/config/setup.yaml` even under `ML4T_OUTPUT_DIR` are `feature_storage_dtype`, `get_classification_eval_label`, `get_direction_labels` and `load_evaluation_config` (which falls back to the source copy), so a scratch dir without `config/` cannot silently answer "nothing declared".
9. `config/backtest/base.yaml`: engine uses the repo copy, the price loader consults the experiment copy (bid/ask columns); treat as read-only.
10. `14_backtest.py` always backtests the validation split; the holdout is evaluated once in `18`/`19`/`20`. Do not repurpose `SPLIT`. `TOP_K`, `MAX_SYMBOLS`, `TOP_N_PREDICTIONS`, `FORCE_REBACKTEST` scope the run, not the economics.
11. Determinism: every preset `seed 42`; `build_training_spec(seed=DEFAULT_SEED)`; LightGBM CUDA is not bitwise reproducible vs CPU ("the repository is the current value and the book is the value at the time of writing").
