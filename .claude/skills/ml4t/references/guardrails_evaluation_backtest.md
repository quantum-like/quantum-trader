## 6. Splits, cross-validation and evaluation protocol

- **Label leakage at the fold boundary** — forward labels of horizon h near the boundary embed validation prices; a 21-day label resolves inside the next window; an unpurged boundary also contaminates conformal calibration residuals / inflated validation scores, silently / purge `label_horizon` sessions (`label_horizon` in `WalkForwardCV` / `CombinatorialCV`, `label_buffer="21D"`); assert `va[0] − tr[−1] − 1 == h` on the sorted unique-date vector (never on panel rows) and `min(purge_gaps) >= horizon`; embargo cutoff at `−(LABEL_HORIZON + 1)`; intraday purge H+1 (16/6/61/16 min) because entry at next-bar VWAP and exit H later consumes t+H+1; library default `label_horizon=0` purges nothing, always pass the true horizon (ch06, ch07, ch09, ch11, ch12, ch13, ch15, ch19, lib_diagnostic, cs_etfs, cs_nasdaq).
- **Missing embargo** — backward-looking features of post-validation training rows consume validation prices in CPCV/k-fold, and validation labels resolve inside the training block that follows / zero in pure forward walk-forward (the purge `va[0] − tr[−1] − 1 == h` is the only boundary rule there); wherever training can follow a test block, purge by label-interval overlap in both directions and set `embargo_size >= max(feature lookback, maximum label horizon)` after the block, or `embargo_pct=0.01` of T when that span is short relative to T (`EMBARGO_PERIODS = 3` in ch15); variable horizons by interval overlap, never a fixed count; `embargo_size`/`embargo_td` and `embargo_pct` are mutually exclusive and `embargo_size` is a no-op in forward `WalkForwardCV`; splitter aliases resolve to canonical keys (`label_buffer -> label_horizon`, `feature_buffer -> embargo_td`, `val_size -> test_size`, `holdout_start/end -> test_start/end`, `calendar -> calendar_id`) (ch06, ch15, lib_diagnostic).
- **Shuffled or random splits on time series** — trains on the future to predict the past; `CalibratedClassifierCV` and domain-classifier CV default to non-chronological folds; random TSTR splits leak / chronological walk-forward only (`TRAIN_FRACTION = 0.7` earliest); `shuffle=True` with `dates` raises in `train_test_split`; expanding chronological calibration splits with a 21-session purge; contiguous relative-time blocks (`DOMAIN_CV_TIME_BLOCKS=20`) (ch05, ch06, ch11, ch19, lib_engineer).
- **Split by date, never by row position** — a row-offset cut puts one decision date on both sides and cuts cross-sections; CV folds, `block_permute` and temporal halves counted in rows become a handful of entities on one day / compute boundaries on unique dates and assign each example by date; mask on timestamp groups; the cut moves to the last timestamp-change index so equal timestamps stay together; pass `groups`/`units` to `block_permute` (ch12, ch13, ch15, lib_engineer).
- **Input windows across a boundary are NOT leakage** — the past is available at decision time / purge only on the label side; partition DL examples by target date (ch13).
- **Holdout contamination** — any development decision made with the holdout destroys the unbiased estimate; sweeps clamp `END_DATE` from `evaluation.holdout_start` in `setup.yaml`; the holdout is spent once at the end against the whole candidate set / set `holdout_start`/`holdout_end` at the start; open once for confirmation; compute labels from already-filtered prices; summaries (mean, spread, median, null-count) only over the development period, shape counts may span the whole; `refuse_a_second_look` and `_refuse_a_selection_disagreement`; software cannot prevent "run 500 times and quote the best" — conduct rule: ask once (ch06, ch08, ch11, ch13, ch14, ch17, ch20, cs_fx, cs_sp500opt, cs_sp500eo).
- **Holdout boundary by label END date** — a row observed before `holdout_start` whose outcome resolves inside it is a holdout row; a trade opened before and expiring inside is a holdout trade / assign every row to development or holdout by its label END (settlement) date: for a fixed h-session label this equals decisions at or before `holdout_start − h − 1` on each instrument's own sessions (`LAST_SCORABLE_DECISION_DATE = pre_holdout_sessions[-(h+1)]`, `fold_boundary_date`, NYSE calendar; `holdout_endpoint_cutoff` = the last decision date whose outcome resolves before the holdout, within session intraday), for variable realized horizons (options held to expiry with `labels.buffer: 35D` = a full option cycle, prediction markets, trend-scanning) it does not, so use the settlement date directly; snap `holdout_start`/`holdout_end` to exchange sessions (a holiday as `holdout_start` is a bug); seal diagnostics on `_label_end = timestamp.shift(-h).over(symbol) < HOLDOUT_START`; score the holdout once on a date >= last holdout decision + horizon cap (+ settlement or dispute allowance) with a pre-declared rule for positions still unresolved on that date (mark at bid and list separately, or exclude); training cut at `LABEL_AVAILABLE_AS_OF = days_before_live[-H-1]` for live (ch06, ch25, cs_fx, cs_sp500eo, cs_usequities, cs_sp500opt, cs_cme, cs_etfs, cs_nasdaq).
- **Refit window uses the widest label buffer** — the same training window serves whichever label selection landed on; a 1D buffer leaves ~three weeks of `fwd_ret_21d` outcomes reachable (inference on count) / end training 21 observations (not calendar days) before the first holdout session; crypto: `holdout_start − 24H`, refused to default to zero; read the label from the selected lineage and step back along its observation grid (cs_fx, cs_crypto).
- **Holdout scored with the validation-fitted model** — circular ("already happened once here"; a registry actually contained such a set) / refit with training ending `labels.buffer` before the window; assert `holdout training hash != validation training hash`, raise "did not refit"; `registered_holdout_generations` flags "VALIDATION-FITTED − not out of sample"; retire via lifecycle (`holdout_generations_to_retire`), never row deletion (cs_sp500opt, cs_usequities, cs_usfirm, cs_nasdaq, cs_cme, cs_etfs).
- **Second configuration on the holdout** — spends the window again; nothing on the holdout may revise the selection / 18/19 refuse a different configuration; reruns of the same one are idempotent; a changed selection goes through the registry lifecycle; carry rank-1 even with negative validation Sharpe; the holdout "is allowed to answer no" (cs_fx, cs_sp500opt, cs_usequities, cs_nasdaq, cs_usfirm).
- **Hand-written or re-split folds** — hand-written walk-forward windows are free to leak; a figure that re-splits disagreed by 11 days; typed fold-boundary dates go stale / hand the WHOLE sample (holdout included) to `generate_cv_splits`, draw folds with `fold_timeline` from returned boundaries; resolve folds from the label file; `REFERENCE_START`, `TRAINING_START/END`, `AS_OF_DATE` default `None` and derive from `setup.yaml` fold geometry (cs_etfs, cs_usequities, ch26).
- **Fold scheme coverage and clipped windows** — `min_train_pct=0.2`, 5 folds x 63 days left the last decade unevaluated; a rolling window longer than history clips early folds to expanding silently / print fold-date span and coverage share; check each fold's train length; match train window and fold count to history (6M–10Y, 2–16 folds) (ch06, ch07).
- **Nested CV and hyperparameter staleness** — selecting and scoring on the same folds inflates; λ tuned once on old years; inner loops without purge; an inner loop producing no folds leaves Optuna returning the sampler's first try / nested walk-forward; inner `WalkForwardCV` with `label_horizon=21`, `embargo_size=21`, test_size ≥ label horizon; record pruned folds as missing; require stability across outer folds (ch06, ch11).
- **Preprocessing fit on the full data** — scalers, imputers, encoders, winsor bounds, PCA, clip quantiles, VWAP profiles, state bins leak future statistics; small per feature, accumulates across dozens / `SplitAwarePreprocessor` / `ml4t.engineer.preprocessing` fit on train per fold (`fold_scaler = scaler.clone()`; `scaler.statistics` must not change after `transform(test)`); `winsorize_train_test` (1st/99th); `handle_unknown="ignore"`; per fold median-impute then standardize on training rows (linear, TabM; GBM leaves NaN); persist the scaler with the model; `get_feature_percentiles(train_indices)` (ch05, ch07, ch11, ch13, ch15, ch18, ch23, ch25, lib_engineer).
- **Calibration set reused** — calibration residuals that doubled as the early-stopping set bias conformal intervals optimistic / carve a third dedicated calibration split before training (ch13).
- **Walk-forward folds treated as a holdout** — every choice (C, alpha, threshold) was made on them; validation folds are read many times in 05–14 / reserve an untouched stretch for any P&L claim; call CV inside the training window a stability demonstration; model-notebook ICs are diagnostics, not evidence (ch11, ch17, cs_fx, cs_nasdaq, cs_sp500eo, cs_usfirm).
- **Feature screening or ranking on the wrong window** — ranking features over the full history reads validation/test years; screening on training dates measures fit, not signal (fold-fitted features only exist on validation dates) / ICs on the train split only when there is one split; otherwise screen on the union of validation ranges and seal at `last_signal_date` = the max date whose `timestamp.shift(-21)` < HOLDOUT_START (ch04, cs_etfs).
- **Pooled IC instead of per-date IC** — pooling mixes which days were good with within-day ranking, weights dates by firm count, is dominated by day-level co-movement, and a persistent tilt masquerades as accuracy / cross-sectional IC per date (or session, or month) then average; quantile boundaries within date; net out the session mean; pool only when each period is rank-normalised (ch04, ch07, ch08, ch10, ch14, ch26, cs_usfirm, cs_usequities).
- **Naive t on the IC series** — ICs are serially correlated (overlap, slow common factors); i.i.d. bootstrap invalid; automatic bandwidth `L = 9` from T alone ignores h = 21; a 5-lag HAC on 21-day labels is too short; Newey-West on an unordered `group_by` output "looks like good news" / `compute_ic_hac_stats(series, ic_col="ic", label_horizon=H)` on a chronologically sorted series; `lag = max(horizon−1, nw_auto)` with `nw_auto = max(1, floor(4*(T/100)^(2/9)))` capped at `T//2`; `HAC_MAXLAGS = 21`; verify the HAC CI overlays a stationary block bootstrap (block = horizon); report `naive_t` beside `hac_t`; recompute stored HAC on sorted daily IC with `lag = min(stored, n_days−1)`; `.sort(date_col)` before calling; `cross_sectional_ic_series` sorts (ch07, ch08, ch11, ch24, lib_diagnostic, cs_etfs, cs_cme, cs_crypto, cs_nasdaq, cs_usequities, cs_fx).
- **Headline IC without SE, sign or coverage** — the same IC can be clearly positive or indistinguishable from zero; an inverted ladder means shorting the wrong leg; a model predicting a constant on some dates posts high IC on a self-selected sample ("a metric averaged over a set the model itself selected is not a metric") / report IC, ICIR, HAC t, CI, dispersion; read sign first and at every horizon; read `ic_n_days` / `full_coverage` before `ic_mean`; `ic_mean_daily` from `prediction_metrics`, not the catalog fold mean; assert scored dates > 0 (ch07, ch08, ch12, cs_etfs, cs_fx, cs_sp500eo, cs_usequities, cs_nasdaq).
- **Minimum cross-sections and breadth over time** — rank correlation over too few names is meaningless (2–3 names give ±1); library default `min_obs=10` discards every date in an 8-fund panel; a date with 6 funds and one with 90 weigh equally / `min_obs=5` for 8 ETFs, `MIN_CROSS_SECTION` 20–30, `min_obs = median eligible-per-date // 2` (44), `>= 10` contracts per settlement (186 of 2,189 fall below), `MIN_ASSETS_PER_DATE=10`; `quantile_profile(min_per_bucket=20)`; `analyze_signal(filter_zscore=3.0)` silently drops |z| > 3 factor values per date (`None` disables); drop thin dates rather than average them in; print funds-per-date; subsample by complete dates (`_trim_by_complete_dates`), never `[-MAX_SAMPLES:]` (ch13, ch26, lib_diagnostic, cs_etfs, cs_sp500eo, cs_crypto, cs_nasdaq, cs_usfirm).
- **Permutation null on the wrong unit** — permuting rows iid within date is ~3x (sample size) and ~10x (dependence) too narrow; p printed as 0 / permute fold dates only; block relabeling per label horizon; `p = (r+1)/(B+1)` and print the resolution; block = 1 vs block = h widths (ch07, ch15).
- **Fold summaries as uncertainty** — std of per-fold IC is not an estimator; folds are few, overlapping and disagree in sign (the most adverse fold moves more than the rest combined) / cite `ic_ci_lo/hi`, `ic_t_hac` from the daily series; per-fold IC as a stability box plot; Driscoll-Kraay 95% CI forest plots; a family whose CI crosses zero is "not established", not "fifth" (ch12, ch13, ch23, cs_etfs).
- **Ranking off overlapping individual intervals** — each interval tests one forecaster vs zero; the difference depends on covariance / paired daily (or per-episode) difference and its interval on the same resamples; claim ranking only when the paired interval excludes zero; block bootstrap over contiguous day blocks (`compute_bootstrap_ci`); never subtract summary Sharpes (ch11, ch12, ch14, ch17, ch21, cs_nasdaq, cs_sp500opt).
- **Comparing ICs scored on different days or windows** — a shorter or easier window can win alone; retired generations that scored every day clear the coverage bar (3 of 9 case studies topped by a retired set when omitted); weekly series in a daily pool compare dates not models / `select_rank1` keeps max `ic_n_days`; joins keep `gbm_days == other_days`; mismatches to an "Excluded / Masked for unequal coverage" table, never silently plotted; `exclude_prediction_hashes=_retired`; `common_sample_daily_ic` on intersected keys; one representative (config, checkpoint) per family on full decision-day coverage; "complete" is measured against the case study's own fold grid; `covers_fold_grid`, `MAX_FOLDS` (ch08, ch12, ch13, cs_etfs, cs_nasdaq, cs_usequities, cs_sp500eo).
- **No-parameter baseline** — two models can both be worse than predicting zero and still rank; majority rate is well above 0.5 in a long expansion; a model can beat AUC 0.5 and lose to the accuracy baseline; persistence is hard on prices, weak on returns / always include zero forecast (returns) or persistence (prices), report MSE / zero-MSE with go/no-go < 1; per-fold majority baseline; re-argue the baseline per series (ch10, ch11, ch13).
- **Reading R² out of sample** — intercept shift and noise-amplifying coefficients drive R² < 0 even with correct ranking; rank IC on a price level scores near one / use IC and read R² against zero; cross-sectional IC for multi-asset work (ch11, ch13).
- **IC rising with horizon / half-life markers** — overlap autocorrelates IC and understates SE; a rising profile reads as backwards decay / be skeptical of monotone-in-horizon IC; mark a half-life only after the peak; check `by_label` whether IC rises with horizon; expect thousandths intraday vs hundredths daily (ch07, cs_nasdaq).
- **Significance as tradeability** — a factor can pass the HAC test and lose after costs; a single raw indicator (21-day momentum IC ~0 on ETFs) is not a signal / break-even and cost models (ch16–18); liquidity-bucket IC; feature engineering and model combination (ch07).
- **Strategy-definition hygiene** — beta mistaken for signal (gross quintile returns all sit near the EW benchmark); "net" ambiguity (net of benchmark is not net of costs); the latest month carries the opposite-signed short-term reversal effect; silently changing schedule, mapping, constraints or costs breaks comparability (mechanics drift masquerading as tuning); micro-tuning on simulated P&L overfits; annualizing a monthly sort assumes the edge recurs every month; broad searches on an invalid setup waste effort and inflate trial counts / report net-of-benchmark beside gross and say which "net" (defer cost deduction to the setup's cost model); `SKIP = 1`; version the setup and classify every change; tune on model and signal diagnostics, confirm on strategy outcomes; report in the design's horizon; baseline checkpoint first (ch06).
- **Breadth is not independent bets** — 20 FX pairs among 8 currencies = 5.27 effective bets (`pr = eigenvalues.sum()**2 / (eigenvalues**2).sum()`); ~100 ETFs are not 100 votes; `IR = IC * sqrt(N)` with `REBALANCES_PER_YEAR=252` is an upper bound; cross-sectional dependence inflates effective N (uncorrected limitation) / discount BR for cross-sectional correlation (inference); judge via portfolio backtest; a market-cap filter changes eligible names, not the model (ch08, ch24, cs_fx, cs_usequities).
- **Short track records and lumpy samples** — small IC plus autocorrelation needs large T (1–2 years rarely enough); 2003–2025 holds one severe recession, one pandemic, one inflation episode; two folds with 2020 as one; the ETF long-short t-stat is not significant in the full sample or either era / `min_track_record_ic`; minimum detectable IC from the HAC SE; era stress tests with the failure mode named in advance; caveat every fold-level claim ("enough to say an effect is not large, not enough to characterise one") (ch01, ch06, ch07, cs_sp500opt, cs_sp500eo).
- **Different windows across compared models; stats across unequal windows** — comparisons become partly about the window / intersect indices and assert equality; equal-length windows on both sides (nine SPY windows) (ch01, ch05).
- **Write the IC series first, read it back** — every figure/average must come from the stored copy (`ic_timeseries.parquet`) (cs_fx).
- **Group leakage in supervised discovery** — nodes from the same DAG share a dataset / `StratifiedGroupKFold` with group = dataset id; no cross-fold preprocessing state (ch15).
- **Single chronological split as a ranking** — one split, one seed, no intervals; IC differences within sampling noise / treat as demonstrations; rank only with walk-forward across case studies; multiple 252-session windows for any selection claim (ch13, ch23).

## 7. Multiple testing and selection

- **Selection bias / max of N trials** — the max of N null ICs ≈ sqrt(2 ln N) σ_IC; the best null of 30 shows a respectable Sharpe and high PSR; validation artifact = max over a sweep so every validation→holdout arrow "decays" by construction ("the figure manufactured the decay it was meant to measure"); rank-1 of 3,663 backtests is partly chance / never report the selected statistic uncorrected; BH/Holm/RAS or DSR; log the search-set size; compare like with like (holdout IC vs holdout Sharpe; validation vs holdout Sharpe of the SAME selected configuration); show the distribution each max came from; "winner / champion / verdict" language refused, "holdout decay reading" only (ch05, ch07, ch16, ch17, ch20, ch27, cs_nasdaq, cs_sp500opt).
- **Declared search set** — the set must be fixed by the rules that generated the features before any result is seen; adding candidates after seeing results, or counting only what looked promising, understates K; grid count = product of axes (7x5x4 = 140); abandoned variants are forgotten / trial taxonomy + automatic logging; BH-FDR at `FDR_ALPHA = 0.05` over the whole declared set (40 features, 5 in 04; ~63 columns; ~50 candidates: plain threshold passes 13 of 49, overlap-corrected 3, FDR none); count configs x checkpoints x portfolio sizes as the trial count; K includes all label variants (~2,300 backtests from `fwd_ret_1m_win` and `fwd_class_1m`) but excludes superseded generations; record the arm in the ledger `note` (ch08, ch16, cs_sp500opt, cs_sp500eo, cs_fx, cs_crypto, cs_nasdaq, cs_usfirm, cs_usequities).
- **Naive p-values into corrections / wrong `label_horizon`** — dependence passes straight through; omitting `label_horizon` infers bandwidth from T and emits an anti-conservative warning / `compute_ic_hac_stats` p-values with the real horizon: `NON_OVERLAPPING` (1) for independent periods, 5/21/63 for daily-sampled multi-day returns (ch07).
- **FDR and HAC are different corrections** — one corrects for feature count, the other for one feature's persistence; on a 1-session label NW costs almost nothing while FDR still bites / apply both and report separately; print the three counts (naive |t| > 1.96, HAC |t| > 1.96, FDR rejected) and `survivor_share` (a naive t of ~10 is worth ~3 after overlap correction) (cs_usequities, cs_etfs).
- **Correlated candidates under BH** — a feature and its within-session rank give identical IC yet count twice; overlapping return windows make the effective number of tests smaller so BH is conservative; `FDRSettings` warns because BH assumes independence/PRDS / cluster near-duplicates on 1 − |corr| at `REDUNDANCY_CUT = 0.70` (Spearman over every ~200th date; 22 clusters) and name one representative; count evidence not columns (4 premium features = 1 ordering); use the stability route to PROCEED (effect-size floor + fold sign consistency), never read PROCEED as a stricter BH; compare PROCEED only within a case study (floors differ 0.003–0.01), BH-FDR across (ch20, lib_diagnostic, cs_usequities, cs_usfirm, cs_crypto, cs_etfs).
- **Exploration vs confirmation** — exploration-pass discovery rates inflate; an exploration-route promotion "has not been confirmed by anything" / 80/20 exploration (alpha 0.10) then confirmation on held-out data (alpha 0.05); promote on fold stability; triage STOP if coverage < 0.70 or staleness > 0.50; PROCEED if `fdr_significant` OR the stability route (`sign_consistency >= 0.60` against the feature's OWN pooled sign AND |mean IC| above the case study's effect-size floor; both are constants of each case study's evaluation screen, not `setup.yaml` keys: 0.60 / 0.01 in cs_etfs, cs_usfirm and cs_sp500opt, 0.60 / 0.008 in cs_cme, 0.60 / 0.005 in cs_fx, cs_sp500eo and cs_crypto; ch20 quotes the spread of floors as 0.003–0.01); REVISE for `date_level_feature`, `insufficient_data`, `not_significant_standalone`; the screen is evidence, not a filter (model notebooks train on the whole matrix); nothing downstream filters on the triage ledger except `20_strategy_synthesis/02_feature_evaluation.py` (ch07, ch20, cs_etfs, cs_fx, cs_nasdaq, cs_sp500eo, cs_cme, cs_crypto, cs_usfirm, cs_sp500opt).
- **Stability cut on share of positive IC** — contradicts |IC| selection; a steady inverse predictor scores zero / cut on sign consistency (max of positive share, negative share) at 80% in the ch08 feature-selection sweep (`STABILITY_MIN_SIGN_CONSISTENCY_PCT = 80`, bootstrap resamples) and the ch11 coefficient-sign check (`SIGN_STABLE_MIN = 0.8`), while every case-study triage ledger uses 0.60 across validation folds (previous item); count folds agreeing with the feature's own sign; derive the reported sign from counts (ch08, ch11, cs_usequities, cs_nasdaq).
- **Rademacher anti-serum (RAS) scales** — a standardized R_hat deducted from an IC rejects everything; kappa from the averaged IC invalidates Hoeffding; data-dependent kappa has no coverage guarantee; annualizing or demeaning before RAS mixes units (hourly series under-charged ~6x) / Massart ratio on standardized ICs, deduction in IC units, print both; `KAPPA = 1.0` for inference (empirical max as sensitivity); fix the bound before seeing data; per-period volatility-standardized (ddof=1), non-demeaned returns, annualize last; print `data_snooping_penalty` and `estimation_error`; library RAS `delta=0.05`, `kappa=0.02`; more observations shrink estimation error, not `2*R_hat` (ch07, ch16, lib_diagnostic).
- **Effective number of trials** — 100 variants are not 100 trials (over-penalises); raw count with correlated candidates over-deflates; never drop a correlated set to independence; trial variance measured across 100 trials swings by a third between draws / Rademacher `complexity_ratio`; `effective_number_of_trials` / `K_eff` (floored at `min_k_eff`, `effective_trials` and `correlation_method` mutually exclusive); feed ALL variants to `compute_selection_adjustment`; `DSRSettings.check_n_trials` warns on suspiciously low counts; disclose variance uncertainty (ch07, ch16, lib_diagnostic).
- **DSR mechanics and misreads** — `sharpe_ratio`, `expected_max_sharpe`, `deflated_sharpe` are per period while `sharpe_ratio_annualized` is annualized (a sqrt(252) factor between rows); DSR is a tail probability, RAS a lower bound; non-normality raises DSR when SR_hat < benchmark and lowers it above / annualize all rows before tabulating; threshold = `benchmark_sharpe + sqrt(variance_trials) * [(1−γ) Φ⁻¹(1−1/K) + γ Φ⁻¹(1−1/(K e))]`, γ = 0.5772156649; PSR variance `1 − skew*SR + (kurt−1)/4 * SR²`; PSR for a single strategy, DSR for a selected one; tearsheets compute undeflated DSR unless `n_trials` is passed; DSR deflated over the full declared grid size K (under-deflation from a smaller stage is the failure the check catches); "read a deflated Sharpe as the price of having searched" (ch07, ch16, lib_diagnostic, cs_sp500opt, cs_etfs).
- **PBO misread or faked** — a no-edge selection sits AT 0.5 and sampling error on 50 combos is wide; independent IS/OOS matrices do not implement PBO; a decayed edge is flagged unstable with non-exchangeable blocks / want PBO near 0 and the IS-best near the top OOS; each row = one complementary split of the same series; CSCV needs ≥ 2 folds and ≥ 2 variants, `C(n, n/2)` combinations; PBO is a model-selection diagnostic kept separate from DSR; two-fold PBO is too coarse either way (ch07, ch16, lib_diagnostic, cs_sp500eo).
- **MinTRL and track length** — low Sharpes need > 10 years unsearched and `never` after a handful of candidates; SE ~1 on one year of daily data / `compute_min_trl` / `min_trl_fwer` with the search's `variance_trials`; report PSR/CI; note the `_mintrl_color` ratio `observed_sr / min_trl` looks dimensionally inconsistent (inference: intended `current_periods / min_trl`) (ch07, ch16, lib_diagnostic).
- **Grid readings and post-selection p** — 30 cells yield 1–2 false positives by chance; picking feature + horizon by looking at the scan must be paid for; sign flips across three regimes are three tests with chosen split points / BH across the whole grid, star corrected cells; carry the grid-wide decision beside the raw p; require IC range ≥ 0.04 before building interactions and add them to the searched count; one knob at a time in sweeps (ch07, ch08).
- **Mechanism checks: colliders, confounders and low-power flips** — conditioning on a common effect (fund flows) manufactures association; bivariate checks miss multivariate confounders (the most dangerous confounders are other features); small wrong-sign ICs in subsamples are noise; shifted rolling features share (L − Δ)/L inputs so placebo persistence is mechanical / draw the DAG first and never condition on variables caused by both feature and label; Ch15 partial IC, DML and sensitivity analysis; STOP only if the opposite-sign |t| > 2 AND the unconditional IC is not significant; treat placebo persistence as a diagnostic, not a gate, and weight lags beyond the lookback (252d for 12-1) (ch07).
- **Best lookback from a sweep** — the maximum of N correlated estimates is biased upward / apply RAS; require a broad near-optimal region (≥ 90% of peak), not a point; read the ridge-path shape with HAC bands, neighbouring alphas are usually indistinguishable (ch08, ch11).
- **Event-window search** — extending the CAAR window until the band excludes zero; pre-event drift in signal-triggered studies; event clustering; overlapping estimation and event windows; ~100 breakouts on 5 ETFs / fix the window in advance; report the post-event window separately; clustered SEs or one event per day (BMP/Corrado); `min_gap_days=21` (30 in text); integer offsets on one shared date index; events lacking full windows rejected with `EventRejectionReason` (ch08, lib_diagnostic).
- **Harvey bar on published factors** — survivors were selected on t = 2 / apply t ≥ 3 to the Newey-West mean-return t-stat, not to Sharpe; scale the bar to candidates tried (ch17).
- **Checkpoints and epochs as hidden trials** — keeping a config's best iteration reports the max of 10/8/20 numbers as one; `epoch_at_high` is post-hoc; "epoch where validation Sharpe was highest" wins a validation-Sharpe contest by construction; eight near-identical checkpoints of one network make an allocator comparison a measurement of one prediction / register every checkpoint as its own candidate; ensemble members enter at `checkpoint: last`; schedule from physical epochs; `checkpoint_dominates`, `epoch_against_capacity`; cap `checkpoints_per_config`; count distinct configurations with `top_n_cap` (cs_fx, cs_sp500eo, cs_usequities, cs_usfirm, cs_nasdaq, cs_etfs, cs_sp500opt).

## 9. Backtesting

- **Same-bar look-ahead** — a close-derived signal filled at that close earns a return that began before the signal existed; `SAME_BAR` and `vectorbt` preset curves are "what same-bar filling is worth" / shift the whole weight matrix or entry/exit conditions one row; `ExecutionMode.NEXT_BAR` (decide close t, fill open t+1); a bar's total volume is known only at close (pass accumulated or lagged volume); trade one bar after the scored bar (`next_bar_open_or_vwap`) (ch16, ch18, cs_nasdaq, cs_sp500eo).

- **No holdout / term-sheet drift / parameter-sweep selection** — every reported date built or chose the rule; criteria adjusted to the output; the highest in-sample Sharpe cell is not a validated choice / label "in-sample teaching output"; write floor, drawdown limit and benchmark condition first and score pass/fail; read the surface for flatness; no holdout means no deployment claim; DSR/RAS (ch16).
- **Accounting defects** — negative-cash financing from simultaneous full-notional rebalances; double-charging slippage already in fill prices; `reference_price` from a different surface; open positions in round-trip stats; fill vs trade counts conflated; win rate inflated by open trades; cost waterfall measured from first close / sell first, deduct fees, scale buys, or `reject_on_insufficient_cash=True`; assert net P&L == change in account value; recover the base price from the slipped fill and side; closed trades only (`status="closed"`); `num_fills` for activity; measure from starting capital; `num_trades` is NULL on the vectorized path (report none, not zero) (ch16, ch19, cs_cme).
- **Futures mechanics** — missing multiplier (P&L, margin, valuation wrong by the point value); % of notional cannot reproduce $/contract; ratio-adjusted continuous series exclude roll orders and costs; margins anchored to 2025-12-31 applied to 2018–2023; a deferred CL contract settled below zero on 2020-04-20 / `ContractSpec` via `contract_specs=`, verify point value == tick value / tick size, replay with multiplier 1; `CommissionType.PER_CONTRACT`; raw front close for contract counts; null (never clip) non-positive prices `when(col > 0).then(col)` once at load; restore `contract_specs`, `futures_market`, `prices` digests and `entity_contract` in cloned specs or P&L is in wrong units (ch16, cs_cme).
- **Benchmark protocol** — fills+fees vs a frictionless series; a benchmark that trades during warm-up dominates a trending sample; VectorBT's implicit benchmark / run 60/40 or buy-and-hold through the same simulator, dates, prices, fees, slippage, capital fraction; benchmark enters on the first bar the strategy could trade (ch16).
- **Metric conventions and alignment** — hand-rolled Sharpe off by the annualization factor or risk-free convention; one series a day shorter shifts every benchmark-relative number; activity annualized by row count / 365; correlation ~1 as a parity test hides a constant compounding gap / assert agreement with `PortfolioAnalysis` to display precision; one-to-one date join with assertions; elapsed interval between first and last observation; compare terminal wealth and the equity difference over time (ch16).
- **Engine configuration** — unreachable fields (`FillOrdering` measured zero because `TargetWeightExecutor` sorts sells first upstream); inherited presets drift; whole-share disappearance (orders < half a share never submit); integer truncation on BTC; target weight 1.0 with next-open fills; cash-buffer drag; under-capitalised integer sizing ($100k x top_k=20 x integer shares almost never trades) / change the field and confirm something moved; set every execution field explicitly; a `commission_rate` or `slippage_rate` is charged only when the matching `commission_type` / `slippage_type` is set (`CommissionType.PERCENTAGE`, `SlippageType.PERCENTAGE`; the defaults `NONE` ignore every rate field, so a config that sets only rates runs cost-free), and the "moved" check is a positive total commission in the result; `ShareType.FRACTIONAL` or `initial_cash: 1_000_000` with `share_type: integer`; position size 0.95; charge the buffer to the engine requiring it; read `initial_cash`, `share_type`, `allocator_lookback` via `get_backtest_config()` (spec-hash inputs; a local constant invalidates every `backtest_hash`) (ch16, cs_sp500eo, cs_sp500opt, cs_nasdaq, cs_usequities, cs_etfs).
- **Decomposition and tie handling** — levers that change holdings change what others trade; sorting an all-equal cross-section returns file order; rows summing to 1 − 1e-16 under-hold / measure the bundle and the parts, report the residual as interaction; equal-weight the universe on all-equal dates and count them; secondary sort by symbol; push residue onto one held asset and assert exact row sums (ch16).
- **Adaptive logic and halts** — feedback loops that never fire look adaptive; a circuit-breaker halt leaves equity unable to recover; `MaxDrawdownLimit` / `DailyLossLimit` as sweep variants yield zero-std Sharpe artifacts; a post-halt tracked index is not money anyone made / report the realized range of target fractions; explicit reset / re-entry protocol; keep portfolio-level limits as governance, sweep position-level rules only (ch16, ch26, cs_nasdaq).
- **Signal conversion** — fixed thresholds on uncalibrated scores become always-on or never-on; trailing percentiles with too little history; cross-sectional rules on a thin universe; transition rate read as turnover; settings carried between strategies; the artifact selected by the statistic compared / detect activation near 0 or 1; percentile rules with lookbacks 21–63 and `>= longest lookback` observations; `>= 2` symbols per date; turnover from fills; re-run diagnostics per score stream; rule-based selection (widest coverage, hash tie-break) and recompute rank IC and n_days against registry metadata (ch16).
- **Regime slices and conditional paths** — thin slices with no valid naive CI under overlap; slice drawdown "a path no account followed"; restricted-stream max drawdown −76.9% vs −55.4% concatenates losses from different decades / read `days`/`share` first; compare states only, calendar episodes for lived experience; means survive conditioning, path statistics do not; one-day conditional metrics; prefer the `macro_regimes` construction (ch01, ch16, ch19).
- **Sharpe inference on a backtest** — Sharpe without sample length (SE ~1 on one year daily); normal assumption on fat tails; Lo's correction on short samples (ρ_k SE ~1/sqrt(T), yearly multipliers range ~5 units); asymptotic variance on short records; synthetic iid paths / PSR/CI, MinTRL; feed sample skew and kurtosis; Lo as a diagnostic computed per year; `< 4` finite returns or `std <= 1e-10` refused; dependence-aware resampling (ch16, lib_diagnostic).
- **Plumbing test with a no-information signal** — profit on random scores means the pipeline (fill timing, join, cost model) is the alpha / run `score_weighted_top_k` at the smallest feasible `top_k` with random ranking before any real signal; PASS iff |Sharpe| < `PLUMBING_SHARPE_TOLERANCE = 1.5`; random scores must be clearly negative after costs at 15 min; seeded (`SEED = 42`) smoke test catches gross engine bias only, not research-choice bias (cs_etfs, cs_nasdaq, cs_usfirm, cs_sp500eo).
- **Engine built-ins: lifecycle and account policy (read before overriding)** — point-in-time loop (strategies see only the current bar; `_validate_strategy_lifecycle`); single-use `Engine` with append-only journals (`_run_once`, `TargetWeightExecutor.reset()`); `_validate_completed_run`; `AccountPolicy` gatekeeper at fill price (`submit_order` returns `None`, `last_rejection_reason()`, `to_rejected_orders_dataframe()`); Reg T margins (`initial_margin=0.5`, long 0.25, short 0.30) and `short_cash_policy` (`credit` / `credit_proceeds` / `lock_notional`); `settlement_delay`, `available = spendable * (1 − cash_buffer_pct)`; `get_max_affordable_quantity` bisection minus `CASH_TOLERANCE = 0.01`; lifecycle rollback; artifact integrity errors (lib_backtest).
- **Engine built-ins: fills, stops and bar-path ambiguity** — exit-first fill ordering (alternatives `fifo`, `sequential`, `priority`); `FillEngine.check_fill` (LIMIT only if `low <= limit` / `high >= limit`; STOP fills at the open when gapped through; TRAILING_STOP ratchets one way); `_risk_fill_price` with `stop_slippage_rate`; `_evaluate_path` takes the worse of high-first/low-first (`AmbiguousBarPathError`); `TrailStopTiming.LAGGED`; `StopFillMode.STOP_PRICE`; funding before fills; non-negative cost models; `add_with_zero_cancellation` (lib_backtest).
- **Engine built-ins: schedules, data policies and rebalancer caps** — `MissingPricePolicy.SKIP`, `LateAssetPolicy.REQUIRE_HISTORY`; `config.validate()` warnings; `enforce_sessions=True`; strict causal schedules (`should_rebalance` must see every event, alignment errors name the nearest event); pre-open causality (`LateAuctionIntentError`); rebalancer caps (`max_gross_leverage`, `max_single_weight`, `min_weight_change`, `min_trade_value`, `cancel_before_rebalance`); `reduce` only on `MaxDrawdownLimit`; no automatic end-of-data flattening (`ExitReason.END_OF_DATA`; flatten in `on_end`) (lib_backtest).
- **Engine non-coverage and parity scope** — corporate actions, borrow costs, taxes and currency conversion are NOT modeled; bar data cannot order intrabar events; parity runs disable costs and position rules so a VectorBT match is not tradability; parity audits test target replay under pinned versions / adjust prices upstream; treat dividend-paying or hard-to-borrow names as optimistic; switch to `realistic` costs; never approximate an unsupported asset model to add a row; keep synthetic stress rows separate; do not generalize engine timings (ch16, lib_backtest).
- **Options engine** — the shared vectorized backtester on `ret_to_expiry` assumes one position per symbol and no premium MTM; 5d/10d labels on the vectorized path give Sharpe ~6.5; `total_slippage` NULL on all 879 rows is not "no costs"; vectorized Sharpes cannot anchor HTM runs; a risk overlay silently discarded by cohort-normalised weights / `_run_htm_daily_mtm` with 5 cohorts at 1/5 capital; `variants: []`; only HTM-dispatched backtests enter comparisons; the execution path refuses a risk block and 14 proves the store unchanged (cs_sp500opt).
- **Coverage and holding-slot contracts** — a decision at a timestamp the panel does not hold; `advance == step` asserted (tautology for cross-sectional families, false for sequence families); infeasible k (`2k > tradeable`); per-decision fill `min(k, n/2)` (top-5 narrows at 186 decisions); a never-trading book reports Sharpe 0.0 and wins / `holding_slots` raises; `check_prediction_coverage(decision_axis=CLOCK timestamps, raise_on_gap=False)`, `gap_policy` excuses only `missing_sessions`, `CoverageError` on `missing_fold`, `undeclared_fold`, `out_of_window`, `unaccounted_window`; `get_entry_schemes_for` drops infeasible k; raise when every `top_k` is at or above the tradeable count; `top_n_cap(0) -> None`, negative → ValueError (cs_crypto, cs_cme, cs_etfs).
- **Allocator warm-up prices** — the first weeks trade on median-imputed fallback weights; `compute_hrp_weights` falls back to equal weight on short history and reads as decay / `strategy_warmup_periods` → `load_backtest_prices_for(warmup_periods=...)` (moment allocators 240, score/conformal 0; HRP 63 bars); moment-based allocators rebuild per decision from strictly prior history and the warm-up prefix is not scored (cs_crypto, cs_cme).
- **Risk overlays that never reach the engine** — a flat risk mapping installs nothing yet hashes as a distinct result (56 rows in a retired generation); controls declared but uninstalled; overlay matching the unprotected book everywhere; filtering overlays by equal `traded_folds` removes exactly the controls that fire / `as_risk_spec` `{"name", "position_rules": [{"type", "threshold"|"bars"}]}`; exclude `overlay_without_rule`; raise if every control is inert; check `risk_triggers > 0` (installed-and-never-triggered is valid); count flattened sessions as `(overlay == 0.0) & (baseline != 0.0)`; one rule per request, `_build_position_rules` raises on unknown types; read each overlay against its own un-overlaid parent (cs_crypto, cs_usequities, cs_cme, cs_etfs).
- **Carrier resolution and lineage** — copying a hash between notebooks goes stale on the next sweep; resolver matching on name only; an empty holdout query read as "no strategy"; ambiguous holdout prediction sets; a mis-reconstructed `backtest_hash` (`f23ff90cf518` vs `b2acfd5420c8`) / `resolve_solvent_carrier` in every notebook (raises on `max_drawdown <= -1.0`, retired conformal `calibration_version != "walk_forward_v3"`, ambiguity); never fall through to the runner-up (fix the sweep or pin in `CARRIER_PINS`, re-derived after a rebuild); find holdout sets by derived `(training_hash, checkpoint)`, never by best holdout Sharpe or search; guard on the full prospective `backtest_hash` from `backtest_run_status`; name a missing refit explicitly (`status.found`); refit and backtest in separate notebooks; lineage by `holdout_backtest_hash`, never `stage='holdout'` alone; a cost curve counts for the carrier only when the sweep sits on the carrier's lineage AND runs the carrier's strategy (NASDAQ-100 has 24 `equal_weight_top_k` sweep rows while its carrier is `slot_persistent_signal_exit`; the loader prints the dropped check, absence is read, not guessed); record which baseline an overlay delta was taken against (a signal-stage fallback and an allocation baseline are not comparable) (ch20, cs_cme, cs_crypto, cs_fx, cs_usequities, cs_nasdaq, cs_usfirm).
